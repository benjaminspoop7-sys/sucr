Sucr — visual system, v2

Flat, Material-adjacent, matched to the accepted mark. No gradients, no glow, no shadows doing layout work. Every number printed next to a swatch is measured — WCAG 2.1 relative luminance, foreground against the surface named in its label. Gates: ≥4.5 body text, ≥3.0 20px+ display and meaningful non-text, ≥1.5 adjacent fills — and where 1.5 is unreachable, a shape carries it instead (§Map).

Four of v1's colour claims were false, and a fifth asserted they were all true. Light --text-3 #80868B measured 3.31–3.68 and was used for row metadata; --warning #F9AB00 measured 1.93 and was printed as text; four network hues fell under 3.0 on the deepest light surface; and status colours used as ink on their own tint measured 4.05–4.42. All fixed below, all with the old value shown.

SucrIcon — the bounded set

Lucide geometry, stroke 1.5, 24px grid, currentColor, flat. No filled variant shares a toolbar with a stroked one, and no gradient or glow touches any of them. The eight outlined heavier marks are custom and sit on the same grid — the discipline borrowed from XDM is that one exported enum of named constants is a bounded set, so the set is reviewed when it passes 120 and anything unused for two releases is deleted rather than left in an icons/ folder.

Light

Status — six tiers, and one modifier

Colour is semantic and never decorative: danger only for needs-attention, warning only for a degraded-but-working state, success only for completed-and-verified. The sucker map — and why colour alone cannot draw it

Rows are networks, columns are byte ranges in order, one cell per block. Measured adjacency, the gate being 1.5: against the track every saturated state clears easily (light active 3.74, hedge 4.37, done 4.16, failed 3.96; dark 4.4–5.3). Against each other they do not: light active/hedge 1.17, active/done 1.11, done/failed 1.05; dark has eight such pairs against light's seven, down to active/hedge 1.04 and hedge/done 1.12. Whole families sit inside 1.2 of each other, so luminance cannot carry the distinction and the grid draws every state twice: once in colour, once in shape.

Art — six states that would otherwise be a sentence

Flat inline SVG on a 160×120 grid, 2px stroke at that scale, one accented element per piece and it always carries the meaning. Linework is currentColor at the --text-3 weight, so the art is grey and quiet in both themes and never competes with a status colour. The sucker-dot motif is the only brand carryover into the art; there are no faces, no gradients, no glow, and no filled shapes mixed into a stroked composition. Files live in D:\RE\Sucr\design\art\.

Each piece ships one .svg file, not two: the standalone files carry a <style> whose rules read var(--accent-ink, #1765CC) — resolved from the cascade when inlined in the app, and falling back to the light hex when opened alone. Zero art duplication, zero theme branches.

What this replaces, and what is still a claim I have not earned

Five fixes, all measured

  1. --text-3 was 3.31–3.68 (light) and 3.33–4.19 (dark) while carrying row metadata → now 4.72 / 4.74 on the deepest surface.
  2. --warning #F9AB00 measured 1.93 and the plan printed it as text → split into --warning ink #B63A0A and --warning-fill #F9AB00.
  3. Four of eight network hues fell under 3.0 on --surface-2 (lime 2.25, teal 2.76, amber 2.79, cyan 3.15) → all eight re-picked, all now 3.06–4.92.
  4. Status ink on its own tint — success 4.42, danger 4.05 — is exactly where a badge prints → an -ink token per status, 5.45–6.66 on tint.
  5. Map-state adjacency is 1.04–1.49 between states, unfixable by hue → shape/pattern is now part of the spec, not an accessibility add-on.

Not yet earned

  • Font availability. Inter and Roboto Mono are declared, not vendored. On a machine without them this board renders in Segoe UI and Consolas — the ladder is right, the colour of the type is not yet proven. Subsetting and shipping both is a build task with a real KB cost nobody has measured.
  • No screenshot of the real app exists. Every ratio here is arithmetic on hex pairs. Perceived contrast on a 75 Hz panel at night, and hairline 0.5px rendering on a 1× display at fractional Windows scale, are still unverified. What is measured: on this machine at dpr 1 a declared 0.5px border reports a used value of 1px, so the house hairline is a 2×-and-up feature and the app must not encode a state as a 0.5px/1px difference. Fractional Windows scale (125 %, 150 %) is still untested and could round the other way, to zero.
  • Colour-blind simulation has not been run. The shape rule makes protan/deutan failure unlikely rather than impossible; the hedge hatch at 5px and the 13px cells are the two places a simulation would most plausibly disagree with this page.
  • Provenance. Ratios computed locally with WCAG 2.1 relative luminance; the gate thresholds are the WCAG numbers, not a Sucr invention. No claim on this board is from a run of Plexo or XDM.

Single source of truth is design/tokens.css. This board copies it so the file renders standalone; if the two ever disagree, the token file wins and this page is stale.
